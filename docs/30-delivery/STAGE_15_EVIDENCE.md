The physical table key is user scope + branch scope + whitelisted dataset + opaque 64-character lowercase-hex parameters hash + positive model version. Stage 15 does not derive these scopes from an authenticated session; that binding is a later integration prerequisite. `payload_json` must be syntactically valid JSON, with nonnegative `stored_at_ms` and `validated_at_ms >= stored_at_ms`. No token, credential, authorization header or persisted `is_fresh`/authority Boolean is stored. A future restored snapshot starts stale. Stage 15 does **not** validate hosted business responses or branch authority; that is a later integration prerequisite. The initial table has no business rows at a clean startup because no module calls the store. Synthetic tests use temporary databases only.

Version 0 migrates transactionally to 1; version 1 opens after table verification; a newer version leaves the file intact and degrades the managed state to `Unavailable`. Recoverable path, open, configuration or migration failures do not abort Tauri startup. Rust errors and startup diagnostic text contain categories, not an absolute profile path, raw SQL or business payload. Put/get/delete require a complete typed key, upsert replaces one key atomically, and purge functions target exact user or user+branch scope. ## Correction build evidence
