# Greenfield Stage Gates

No stage is accepted merely because code exists or tests pass.

## Gate 00 — Initialization

Required:

- greenfield Git baseline exists;
- Stage 00 branch based on recorded main SHA;
- hosted reference clone SHA recorded;
- old desktop PASS claims absent from active state;
- legacy docs preserved only as archive if imported;
- Tauri/React/TypeScript scaffold has no demo runtime;
- no fake operational data/status;
- one UI-system direction recorded;
- contract inventory exists;
- security boundary reviewed;
- exact checks recorded;
- evidence status is `READY FOR INDEPENDENT REVIEW`;
- branch pushed if remote exists;
- no merge;
- independent Git review;
- explicit owner confirmation.

## Gate 01 — Auth / Branch / Shell

Required before module work:

- real authenticated identity path;
- authorized branch context;
- fail-closed behavior;
- one runtime shell;
- only active first-release navigation;
- truthful online/offline/connectivity language;
- no fake sync success;
- keyboard/focus baseline;
- viewport checks;
- independent review + owner confirmation.

## Module gate

For every module:

- current hosted contract inventory reconciled;
- authoritative reads connected;
- authorized mutations connected or explicitly unavailable;
- loading/empty/error/offline/stale states;
- no fake records/metrics/success;
- shared shell/primitives reused;
- focused tests;
- keyboard/accessibility checks;
- 1440×900, 1366×768, 1024×768 behavior recorded;
- security/data impact recorded;
- evidence pushed;
- independent Git review;
- owner confirmation.

## Integrated release gate

Requires separate authorization and must include:

- cross-module regression;
- native Windows verification;
- installer/update plan;
- Tauri capability/security review;
- production-target-safe verification;
- rollback;
- owner acceptance.
