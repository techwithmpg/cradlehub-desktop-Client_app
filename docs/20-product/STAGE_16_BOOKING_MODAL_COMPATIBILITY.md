Keep the existing `NewBookingModal` unchanged. The hosted booking POST is a usable Bearer-authenticated mutation boundary, but the hosted modal depends on several cookie-authenticated web routes and Server Actions that cannot be called as desktop APIs. ## Exact mutation and validation constraints

[`createInhouseBookingMultiSchema`](https://github.com/techwithmpg/Cradlehub/blob/2b3bab3c9e71274c25d747daf37d7928ee670e2c/src/lib/validations/booking.ts#L103-L224) accepts `crmBookingMode` (`walkin`, `phone`, `standard_future`, `home_service`), `type` (`walkin` or `home_service`), `deliveryType`, optional `idempotencyKey`, optional `attendees`, optional ordered `serviceLines`, and precise Home Service fields. The top-level `serviceIds` must match the union of attendee service IDs. For single-person booking, `serviceLines` may specify each duration/version; for a group, each attendee carries its own ordered lines. `paymentReceived` defaults false; collection is outside this stage.

[`POST /api/desktop/v1/bookings`](https://github.com/techwithmpg/Cradlehub/blob/2b3bab3c9e71274c25d747daf37d7928ee670e2c/src/app/api/desktop/v1/bookings/route.ts#L49-L127) verifies a Supabase Bearer token and active CRM staff before delegating to the shared engine. The engine checks operator branch, branch rules, service eligibility, quote versions, availability, resources, Home Service dispatch, and atomic creation. The endpoint returns `{ok, bookingId, warning?}` on success. Do not infer a confirmed therapist, room, attendee set, status, or payment result from a provisional preview or from the omitted response fields.

The engine's group path assigns therapists via `assignTherapistsForOrder`; it does not accept exact per-guest staff IDs. The hosted form explicitly refuses group submission when any guest therapist selection is active. Groups use automatic room allocation; a top-level room ID returns `RESOURCE_INVALID`. Consultation-only services can require a coordinating `staffId` and yield a manual-arrangement warning; the hosted form's group submission guard means this is a source-contract tension to resolve before offering that workflow in desktop. Single bookings can submit `staffId`/`resourceId`, but server verification is final. See [engine assignment](https://github.com/techwithmpg/Cradlehub/blob/2b3bab3c9e71274c25d747daf37d7928ee670e2c/src/lib/bookings/inhouse-booking-engine.ts#L286-L375) and [room allocation](https://github.com/techwithmpg/Cradlehub/blob/2b3bab3c9e71274c25d747daf37d7928ee670e2c/src/lib/bookings/inhouse-booking-engine.ts#L403-L505).

The engine uses the supplied idempotency key for order creation and detects a changed-payload replay for group bookings. The hosted form retains one UUID for an unchanged payload until confirmed success. The desktop currently supplies none, while the server can generate a new one. A later stage must keep the same key across timeout retries, reset it only when the meaningful payload changes, and reconcile uncertain outcomes through an authoritative read. The endpoint currently maps several domain errors to HTTP 500 by default, including quote-change/configuration and some Home Service distance failures; preserve the returned code/message and request explicit mapping improvements in a hosted API stage rather than interpreting every 500 as retry-safe.

## Service duration and pricing contract

Hosted [quote calculation](https://github.com/techwithmpg/Cradlehub/blob/2b3bab3c9e71274c25d747daf37d7928ee670e2c/src/lib/services/service-line-quote.ts) has fixed and extendable policies. Fixed services use the branch override duration/price where configured. Extendable services require valid catalog increment, extension price, and maximum, and reject branch custom duration/price. The price is computed in cent precision from base price plus extension units. [Quote versions](https://github.com/techwithmpg/Cradlehub/blob/2b3bab3c9e71274c25d747daf37d7928ee670e2c/src/lib/services/resolve-service-line-quote.ts) are server-issued SHA-256 comparison tokens over branch, service, selected duration and terms; they are not client price authority. [Line resolution](https://github.com/techwithmpg/Cradlehub/blob/2b3bab3c9e71274c25d747daf37d7928ee670e2c/src/lib/services/resolve-booking-line-quotes.ts) requires line order to match service order and rejects stale `expectedQuoteVersion` with `SERVICE_QUOTE_CHANGED`.

The hosted [quote endpoint](https://github.com/techwithmpg/Cradlehub/blob/2b3bab3c9e71274c25d747daf37d7928ee670e2c/src/app/api/booking/service-line-quotes/route.ts) takes branch, service, `audience:"crm"`, and delivery mode, but its CRM authorization uses web cookies. The hosted UI refetches options on duration choice. A desktop Bearer equivalent should return eligible quote options and version without accepting client prices, scope them to authenticated branch/role, reject changed terms, and return meaningful typed errors. The desktop's current `QuickBookingOptionService` and `totalPrice` calculation lack these terms; its totals are only a local preview. No local pricing formula or unverified payment amount may become authority.

## Home Service contract and gap

The hosted [Places widget](https://github.com/techwithmpg/Cradlehub/blob/2b3bab3c9e71274c25d747daf37d7928ee670e2c/src/components/public/places-autocomplete.tsx) requires a selected Google Place with nonempty place ID and formatted address, valid coordinates, and optional address components/map URL. The browser uses a public `NEXT_PUBLIC_GOOGLE_MAPS_BROWSER_KEY`; desktop needs a separately approved client/key restriction strategy. Never bundle a privileged Google server key. Editing the address must clear the selected Place and distance quote. The server [validation](https://github.com/techwithmpg/Cradlehub/blob/2b3bab3c9e71274c25d747daf37d7928ee670e2c/src/lib/validations/booking.ts#L34-L64) requires precise place fields; the engine also checks complete address, eligible services, Home Service hours/rules and dispatch conflict. No room is submitted.

The hosted [distance route](https://github.com/techwithmpg/Cradlehub/blob/2b3bab3c9e71274c25d747daf37d7928ee670e2c/src/app/api/home-service/distance/route.ts) is cookie-authenticated. The [distance service](https://github.com/techwithmpg/Cradlehub/blob/2b3bab3c9e71274c25d747daf37d7928ee670e2c/src/lib/home-service/distance-service.ts#L156-L240) uses Google Routes **driving** distance and server branch rules for base/included-km/per-km fees; it fails closed when a driving route or configuration is unavailable. `quick-booking-form.tsx` still types `haversine_estimate` as a possible source, but current distance-service source only returns `google_driving`. Treat that UI type as stale, not permission to calculate a fallback fee. The engine recalculates the quote and stores a transport snapshot at submission. A desktop Bearer distance-quote contract is required for a trustworthy preview; the server recalculation remains final.

5. Review the booking POST's typed HTTP error mapping and group response fields (`orderId`, attendee/line IDs or a follow-up read) and specify idempotency lookup/reconciliation for an unknown response. These are hosted API changes requiring separate target-aware authorization; Stage 16 changes none of them.
